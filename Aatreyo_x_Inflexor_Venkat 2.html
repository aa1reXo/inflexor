Under the hood

How I'd actually build this

This is the same core architecture I shipped in production at Qualcomm — RAG + MCP tool-calling agents with stateful memory, running on GCP/Vertex AI for 200+ daily users across 55+ teams. Same pattern, different data sources: swap Jira / Axiom / Orbit for deal flow, portfolio metrics, and LP reporting.

Decks, data rooms, portfolio co. updates, public filings

Cross-check every claim against a source — evals before it ships

You've built fixed-income trading systems — you know a pipeline is only as good as what it does when a step fails silently. So here's the contract behind step 02, not just the diagram:

{
  "run_id": "uuid", // idempotency key
  "company": "string",
  "set_classification": "science-led" | "engineering-led" | "technology-led",
  "scores": { "team": 0-100, "tam": 0-100, "technology": 0-100 },
  "confidence": 0.0-1.0,
  "sources": [ "string", ... ],
  "requires_human_review": true | false
}
  • Idempotency key per run — re-running the same deal never double-writes to the deal record.
  • Retries with backoff, then a hard stop — model calls retry on transient failure; a per-run cost ceiling kills the run rather than silently over-spending.
  • Schema validation before a human ever sees it — malformed output triggers one retry, then a manual-review flag. Never a guess dressed up as an answer.
  • Confidence gates review, not the score — if confidence is low, requires_human_review flips to true regardless of how good the numbers look. A high score with low confidence is the failure mode that actually burns trust.
